# フェーズ2：安定性と整合性の確保 - 詳細実装計画書

## 🎯 目的
長期的なプレイにおいて、データの喪失やゲームバランスの崩壊という「致命的なストレス」を排除し、信頼性の高いゲーム環境を提供する。

---

## 🛠 3. ゲームバランスの自動検証システムの構築

### 概要
手動テストでは不可能な回数のシミュレーションを行い、数値的な破綻（無限ループ、一撃死、無敵状態）を自動的に検出する。

### 📝 詳細ステップ (低性能LLM向け小分割)

#### ステップ 3.1: 戦闘シミュレーターの再構築
- [ ] `archive/balance_sim.py` をベースに `tests/balance_simulator.py` を新規作成する。
- [ ] `Engine` をヘッドレスモード（描画なし）で起動し、高速にターンを回す仕組みを実装する。
- [ ] 任意の2つのエンティティ（例：プレイヤーLv1 vs スライム）を戦わせ、結果を記録する `simulate_battle()` 関数を作成する。

#### ステップ 3.2: 統計収集機能の実装
- [ ] 戦闘結果から「平均ダメージ」「生存ターン数」「勝率」を算出するロジックを実装する。
- [ ] 100回以上の試行を行い、標準偏差を計算して「極端な外れ値」を検出する仕組みを作る。
- [ ] 結果を `balance_report.json` に出力する機能を実装する。

#### ステップ 3.3: 異常値検出ルールの定義
- [ ] 「1ターンでHPの100%以上のダメージが出る（一撃死）」を警告とするルールを実装する。
- [ ] 「100ターン経過しても決着がつかない（無敵/低火力）」を警告とするルールを実装する。
- [ ] 特定のスキル組み合わせによる「ダメージ無限増殖」を検出するチェックロジックを追加する。

#### ステップ 3.4: 自動検証パイプラインの構築
- [ ] `data/*.yaml` の主要な設定（攻撃力、防御力、スキル倍率）を変更した際に、自動的にシミュレーターを走らせるスクリプトを作成する。
- [ ] 検証結果をコンソールにサマリー表示し、問題がある場合にのみ詳細レポートを出すようにする。

---

## 🛠 4. セーブデータの堅牢化

### 概要
`pickle` の脆弱性を補い、データの破損からユーザーの努力（プレイ時間）を保護する。

### 📝 詳細ステップ (低性能LLM向け小分割)

#### ステップ 4.1: チェックサムの導入
- [ ] `save_system.py` の `save` メソッド内で、シリアライズ後のバイナリデータから `hashlib.sha256` を使用してチェックサムを計算する。
- [ ] セーブファイル (`savegame.bin`) の先頭または末尾に、このチェックサムを付与して保存する。
- [ ] `load` メソッド内で、保存されたチェックサムと現在のデータのハッシュを比較し、不一致なら `SaveDataCorruptedError` を投げる。

#### ステップ 4.2: 自動バックアップ（ローテーション）の実装
- [ ] `save_system.py` に `create_backup()` メソッドを追加する。
- [ ] セーブ実行直前に、現在の `savegame.bin` を `savegame.bak1`, `savegame.bak2` ... とリネームして保存する（最大3世代）。
- [ ] ロード失敗時に「バックアップから復元しますか？」というダイアログを出す仕組みを `game.py` に追加する。

#### ステップ 4.3: バージョン管理の厳格化
- [ ] セーブデータに `save_version` フィールドを明示的に持たせる。
- [ ] `_ensure_compatibility` メソッドを拡張し、バージョンごとの移行パス（Migration Path）を定義する。
- [ ] 未知のバージョンで保存されたデータをロードしようとした際、安全に拒否する処理を実装する。

## 🛠 5. 体系的なエラーハンドリングの導入

### 概要
「どこで何が起きたか」を明確にし、ゲームを強制終了させずに安全にリカバリさせる。

### 📝 詳細ステップ (低性能LLM向け小分割)

#### ステップ 5.1: カスタム例外クラスの定義
- [ ] `core_framework.py` または新ファイル `exceptions.py` に、ゲーム専用の例外基底クラス `ElonaError` を作成する。
- [ ] `GameLogicError`, `SaveSystemError`, `ConfigError`, `NetworkError` など、カテゴリ別のサブクラスを定義する。

#### ステップ 5.2: グローバル例外キャッチャーの実装
- [ ] `main.py` のメインループを `try...except ElonaError` で囲む。
- [ ] 致命的なエラー以外は、エラー内容を `MessageLog` に出力し、直前のターンをロールバック（または安全な位置へ移動）させる処理を実装する。

#### ステップ 5.3: ユーザー向けエラー通知UI
- [ ] `web_game_client.html` に、エラー発生時に表示される「警告ダイアログ」を実装する。
- [ ] エラーメッセージと共に、「再起動する」「セーブデータをロードする」などの選択肢を提示する。

#### ステップ 5.4: 詳細ログの自動保存
- [ ] 例外発生時に、スタックトレースを含む詳細なログを `logs/error_log_[timestamp].txt` に自動保存する。
- [ ] ユーザーがこのログファイルを開発者に送信しやすいよう、保存パスを通知する。
