# メタプラン: シーズン制ライブコンテンツ・パイプラインの実装計画書作成

## 目的
四半期ごとの期間限定イベント（異界の侵攻、古代文明の覚醒、神々の宴等）をworld_events.yamlでデータ駆動追加し、専用報酬・ランキング・称号を用意する実装計画書を作成する。

## 手順

### ステップ1: 既存のworld_event_systemとworld_events.yamlを調査
- world_event_system.pyを読み解き、現在のイベントトリガー、効果、ストーリーの仕組みを理解する。
- data/world_events.yamlの現在の構造を確認し、拡張点を特定する。

### ステップ2: 9つの提案を検討し、継続的な新規コンテンツ供給とコミュニティ活性化のためのアイデアを出す
- 四半期ごとのイベントサイクルの設計
- イベント固有の報酬システム（アイテム、経験値、特別通貨等）
- ランキングシステム（イベント期間中のポイント競争）
- 称号システム（イベント達成に応じた特別な称号）
- コミュニティ参加を促すイベントデザイン（協力プレイ、競争要素等）
- イベントの予告と告知戦略
- イベント後のフィードバックと次回への引き継ぎ
- イベントバランス調整のためのデータ収集と分析
- イベントリソースの再利用と拡張性の確保

### ステップ3: world_events.yamlのデータ構造を拡張し、季節イベントに必要なフィールドを設計
- イベントID、名前、説明、トリガー条件、期間、効果（既存フィールド）に加え、
- 季節フラグ（quarter: 1,2,3,4 または season: spring, summer, autumn, winter）
- 報酬テーブル（アイテムドロップ、特別報酬条件）
- ランキング設定（ポイント算出方法、ランキング報酬）
- 称号設定（達成条件、称号名、説明）
- イベント画像やサウンドのアセット参照（オプション）

### ステップ4: 実装を36の小さなステップに分割
- 各ステップは1〜2時間で完了できる粒度にする。
- ステップは順序立てて依存関係を考慮する。
- ステップにはファイルの作成、修改、テストが含まれる。

### ステップ5: 詳細な実装計画書（約1万字、日本語）を作成
- 上記の9つの提案を詳細に説明。
- 36のステップを順番にリストアップし、各ステップの目的、作業内容、見積もり時間を記載。
- 必要に応じて図や表を使用。

## 期待される成果
- plans/ディレクトリに「DETAILED_IMPLEMENTATION_PLAN_SEASONAL_LIVE_CONTENT_PIPELINE_1_36.md」という実装計画書が生成される。
- 実装計画書に基づいて、順序よく丁寧に実装を進めることができる。

## 注意点
- 既存のworld_event_systemとの互換性を保つ。
- データ駆動アプローチを維持し、ハードコーディングを避ける。
- テストを忘れずに、各ステップで動作確認を行う。
