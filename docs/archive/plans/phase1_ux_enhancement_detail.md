# フェーズ1：UX基盤の強化 - 詳細実装計画書

## 🎯 目的
プレイヤーが複雑なシステムに圧倒されることなく、直感的にゲームの面白さに到達できる「導入体験」と「フィードバックループ」を構築する。

---

## 🛠 1. インタラクティブ・チュートリアルの実装

### 概要
`HelpSystem` を単なる静的ヘルプから、ゲームの状態に応じてトリガーされる「動的ガイド」へ進化させる。

### 📝 詳細ステップ (低性能LLM向け小分割)

#### ステップ 1.1: ガイドデータ構造の定義
- [ ] `data/tutorial_guides.yaml` を新規作成する。
- [ ] 各ガイドに以下のフィールドを持たせる：
    - `id`: ユニークID
    - `trigger_condition`: 発動条件（例: `first_skill_fusion`, `reach_depth_10`）
    - `title`: ガイドのタイトル
    - `message`: プレイヤーに伝える具体的な指示
    - `action_required`: 完了条件（例: `open_menu_fusion`）
- [ ] `HelpSystem` クラスに `TutorialManager` 内部クラスを追加し、このYAMLをロードする機能を実装する。

#### ステップ 1.2: トリガー検知システムの構築
- [ ] `Engine` クラスに `check_tutorial_triggers()` メソッドを追加する。
- [ ] `EventBus` を利用し、特定のイベント（アイテム入手、メニューオープン、レベルアップ）が発生した際に `TutorialManager` に通知する仕組みを作る。
- [ ] `player` オブジェクトに `completed_tutorials` (set) フィールドを追加し、一度表示したガイドを二度出さないように制御する。

#### ステップ 1.3: UI表示の実装
- [ ] `web_game_client.html` にチュートリアル専用のモーダルウィンドウ（または通知トースト）のHTML/CSSを追加する。
- [ ] `render_system.py` または `web_server.py` を通じて、サーバー側から `TUTORIAL_POPUP` イベントをクライアントに送信し、モーダルを表示させる。
- [ ] モーダルに「閉じる」ボタンと「詳細ヘルプへ」ボタンを実装する。

#### ステップ 1.4: コンテキスト連動の検証
- [ ] 「初めてスキル合成画面を開いた時」に、合成の基本を説明するガイドが出ることを確認する。
- [ ] 「初めて転生した時」に、継承スキルの選び方を説明するガイドが出ることを確認する。

---

## 🛠 2. UI/UXの視認性とフィードバックの強化

### 概要
情報の優先順位を明確にし、重要な出来事を「視覚的・感覚的」に伝えることで、プレイの快感を最大化する。

### 📝 詳細ステップ (低性能LLM向け小分割)

#### ステップ 2.1: 通知レベルの導入
- [ ] `MessageLog` のメッセージ構造を拡張し、`level` (INFO, SUCCESS, WARNING, CRITICAL) を持たせる。
- [ ] `web_game_client.html` のログ表示部分で、`level` に応じたCSSクラス（例: `.log-success { color: #4ade80; font-weight: bold; }`）を適用する。
- [ ] レアアイテム入手時やレベルアップ時に `SUCCESS` レベルのログを出すように `game.py` の各所を修正する。

#### ステップ 2.2: 重要イベントのポップアップ通知
- [ ] 画面中央に短時間表示される「フローティング通知」機能を `web_game_client.html` に実装する。
- [ ] `ui_fx_systems.py` に `NotificationManager` を追加し、重要なイベント（例：称号獲得、クエスト完了）をこのポップアップで通知する。
- [ ] 通知の表示時間（例: 3秒）とフェードアウトアニメーションをCSSで実装する。

#### ステップ 2.3: 視覚的フィードバック（画面エフェクト）の追加
- [ ] `ui_fx_systems.py` に `ScreenShake` クラスを実装する。
- [ ] `web_game_client.html` に画面全体を揺らすCSSアニメーション `.shake` を定義する。
- [ ] 強力な攻撃を受けた際や、ボスを撃破した際に、サーバーから `SCREEN_SHAKE` イベントを送信し、クライアント側で一時的に `.shake` クラスを適用する。

#### ステップ 2.4: ゲージバーの動的演出
- [ ] `GaugeBar` (HP/MP) の値が大きく変動した際、一時的に色が光る（フラッシュする）エフェクトをCSSで実装する。
- [ ] 回復アイテム使用時に、HPバーが滑らかに増加するアニメーション（CSS transition）を最適化する。

#### ステップ 2.5: 統合テスト
- [ ] レアアイテムを入手 $\rightarrow$ ログが緑色になり、画面中央にポップアップが出て、わずかに画面が揺れる、という一連の流れを確認する。
