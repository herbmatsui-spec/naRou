# 残りの既知債務解消および製品品質向上計画（12ステップ詳細計画）

本書は、`naRou` プロジェクトにおけるカバレッジ80%達成および主要9改善案完了後に残された、既知債務（バランススナップショット、敵インテント、スタビリティ調整、メタ介入例外、例外ハンドリングの構造化、および細かい設計不整合）を解消するための12ステップの統合実装計画です。

---

## ステップ一覧

1. **ステップ 1: `balance_snapshot` テスト期待値の整合化**
   - **目的**: テストにおけるバランススナップショット（monster_hp 500 vs 220、exp_next flat 100等）の期待値を、現在のバランス調整済みの値に同期・整合させる。
   - **実装内容**: `tests/test_balance_snapshot.py`（または関連テスト）の期待値を現在の `config/` のパラメータ（例: monster_hp 220, exp_next scale）に更新。
   - **リグレッション防止テスト**: `tests/test_balance_snapshot_regression.py` を作成し、スナップショットパラメータが定常であることを保証。
   - **成果**: バランス系テストの偽陽性・破綻解消。

2. **ステップ 2: `enemy_intent_formation` 予測・挙動テストの修復**
   - **目的**: 敵の行動予測（intent formation）に関する既存テストの不整合を解消する。
   - **実装内容**: `enemy_intent_formation` のモジュールとテストを調査し、ターン数や状態遷移に応じた正しいインテント期待値を修正。
   - **リグレッション防止テスト**: `tests/test_enemy_intent_regression.py` に `assert_distinguishes` を用いた敵意図決定の非空性テストを追加。
   - **成果**: 敵の予測・意図形成機能の完全なテスト緑化。

3. **ステップ 3: `stability` (win_rate 0.22) の原因究明とゲームバランス微調整**
   - **目的**: スタビリティテストにおける `win_rate` 低下（1.0 → 0.22）の原因（バランス調整やAI仕様変更）を分析し、必要に応じたパラメータ補正またはテスト期待値の妥当性確保を行う。
   - **実装内容**: `tests/test_stability.py` のシミュレーションパラメータを確認し、プレイヤー戦闘力・敵難易度のバランスを調整。
   - **リグレッション防止テスト**: 100ターン耐久・平衡状態シミュレーションの決定論的モックテスト。
   - **成果**: スタビリティテストの安定化とゲームプレイの健全性確保。

4. **ステップ 4: `meta_intervention` の `KeyError: 'expel'` 例外解消**
   - **目的**: メタ介入システムにおいて存在しないアクションキー `'expel'` が引かれた際の `KeyError` を防ぐ。
   - **実装内容**: `skill_eater_meta_intervention.py`（または関連モジュール）にフォールバック処理および安全なキーチェックを追加。
   - **リグレッション防止テスト**: `tests/test_bugfix_meta_intervention_expel.py` で不正な介入指示が優雅にハンドリングされることを検証。
   - **成果**: メタ介入関連のクラッシュゼロ化。

5. **ステップ 5: `skill_eater_concept_crystal` の `drop_history` クラス属性共有バグの修復**
   - **目的**: `drop_history` がクラス属性の list で全インスタンス間で共有されている不具合（バッチ2発見）を修正。
   - **実装内容**: `skill_eater_concept_crystal.py` のインスタンス初期化子 (`__init__`) で `self.drop_history = []` に独立初期化。
   - **リグレッション防止テスト**: `tests/test_bugfix_concept_crystal_history.py` で複数インスタンス間の履歴独立性を保証。
   - **成果**: 複数コンセプトクリスタル生成時の独立性担保。

6. **ステップ 6: `skill_eater_crafting_system` の forge 例外経路到達不能の修復**
   - **目的**: 本物の forge 経由で `except ValueError` 経路が `except Exception: pass` に握り潰されている問題を修正。
   - **実装内容**: `skill_eater_crafting_system.py` の `HuskForgeEngine` における例外キャッチを適切に分離（`ValueError` を捕捉してエラー辞書を返上）。
   - **リグレッション防止テスト**: `tests/test_bugfix_husk_forge_exceptions.py` で不正な素材投入時にエラー辞書が正しく返ることをテスト。
   - **成果**: クラフティングUI・エンジン間の堅牢なエラーフィードバック。

7. **ステップ 7: `skill_eater_meta_recipes` の未知入力時 None 返却の厳格化**
   - **目的**: 未知入力時に暗黙の `None` を返している3つのメソッドを、明確な失敗辞書（Error dict / empty payload）返却に変更する。
   - **実装内容**: `skill_eater_meta_recipes.py` の該当メソッドを修正し、呼び出し元が失敗を検知できるようにする。
   - **リグレッション防止テスト**: `tests/test_bugfix_meta_recipes_fallback.py` で未知入力の安全なハンドリングを検証。
   - **成果**: レシピ解析・ネゴシエーションの堅牢性向上。

8. **ステップ 8: `skill_eater_underground_arena` のスコア式（高得点無限増加）の修正**
   - **目的**: 無攻撃 wave 完走時でもスコアが増えてしまう地下闘技場 `complete_wave` のスコア算出式を修正。
   - **実装内容**: `skill_eater_underground_arena.py` でダメージや攻撃回数がゼロの場合のスコア加算を調整（DPS > 0 条件の追加等）。
   - **リグレッション防止テスト**: `tests/test_bugfix_arena_score.py` で無攻撃・低DPS時のスコア停滞を検証。
   - **成果**: 闘技場ランキング・スコアの公平性確保。

9. **ステップ 9: 例外ハンドリングの構造化計画（主要27ファイルの一部集中改善）**
   - **目的**: TODO.mdに挙げられている散在する `# TODO: handle exception properly` のうち、コアシステム（`item_system.py`, `map_engine.py`, `sound_manager.py` 等）の広範な例外握り潰しを構造化ログ・明示的例外送出に置換。
   - **実装内容**: 対象ファイルの汎用 `except:` を特定例外（`ValueError`, `KeyError` 等）の捕捉と `logger.warning`/`error` に書き換え。
   - **リグレッション防止テスト**: 既存のエラーパスカバレッジテストを拡充。
   - **成果**: デバッグ容易性の向上とサイレントバグの排除。

10. **ステップ 10: レイテンシー・フレーキーテストの安定化とタイムアウト調整**
    - **目的**: フレーキーなテスト（パフォーマンス・レイテンシー関連）の環境依存タイミング問題を解消。
    - **実装内容**: テストにおけるスリープや厳密な時間計測の許容誤差を緩和、またはモック化。
    - **リグレッション防止テスト**: 該当テストの連続10回実行による非フレーキー性の確認（CIゲート安定化）。
    - **成果**: テストスイート全体の信頼性向上。

11. **ステップ 11: 総合統合回帰テストの実行（コア・配線・バグ修正・カバレッジ全スイート）**
    - **目的**: ステップ 1〜10 の全変更が既存機能に影響を与えていないかを検証。
    - **実装内容**: コアスイート (160 tests)、配線テスト (29 tests)、バグ修正テスト (14 tests)、カバレッジテスト (427 tests) を一括実行。
    - **リグレッション防止テスト**: フルテストスイート (480+ tests) の全緑化確認。
    - **成果**: 全モジュールの完全な統合状態の証明。

12. **ステップ 12: ドキュメント更新、README実測値同期、および最終アトミックコミット**
    - **目的**: 変更内容を README.md や TODO.md に反映し、綺麗なアトミックコミットとリモートプッシュを行う。
    - **実装内容**: README.md のテスト数・状態の更新、TODO.md の完了項目移動、`git commit` および `git push origin feature/design-v2-impl`。
    - **リグレッション防止テスト**: `python3 -m pytest` および `ruff check .` の最終実行。
    - **成果**: レポジトリの完全な清潔さと最新状態の保持。

---

## 運用規律
- **Green → Green サイクル**: 各ステップごとに必ず対応するテストを実行し、すべてのテストが緑であることを確認してから次へ進む。
- **Atomic Commits**: 各ステップまたは論理的まとまりごとに明確なコミットメッセージを作成。
- **静的解析ゲート**: `ruff check .` によるエラーゼロを維持。
