# 実装計画書：提案3 — §2マッピングの実態ギャップ可視化

- **計画ID**: PLAN-03
- **対象提案**: 9改善提案の「3. §2マッピングの実態ギャップを可視化」
- **作成日**: 2026-08-20
- **スコープ**: 設計ドキュメント（`DESIGN_A_SKILL_EATER.md` §2）と実装・データ実体の乖離を「TBD管理リスト」として可視化する

---

## 1. 背景と問題

`DESIGN_A_SKILL_EATER.md` §2（L26-65）は、naRou基底システムを本ワールド向けにリデザイン・オーバーライドすると謳っている。

| §2項目 | 設計上のマッピング先 |
|---|---|
| 2.1 神々 | gods.yaml → 9柱の概念 |
| 2.2 派閥 | factions.yaml → 商会/戦線/銀行/ブローカー |
| 2.3 ジョブ | jobs.yaml → スキル階級（6階級） |
| 2.4 スキルツリー | skill_trees.yaml → 喰らいツリー（動的） |
| 2.5 ペット | pet_*.yaml → 従属スキル保有者 |
| 2.6 輪廻転生 | reincarnation.yaml → スキル継承 |

**調査結果（PLAN執筆時）**:
- 基底データ `data/gods.yaml`, `factions.yaml`, `jobs.yaml`, `skill_trees.yaml`, `reincarnation.yaml`, `pet_*.yaml`（8ファイル）は存在するが、**汎用・基底**であり skill_eater 固有のオーバーライドではない。
- **skill_eater 固有データは `data/worlds/skill_eater/skills.yaml` のみ**。§2が想定するワールド別データファイルは未存在。
- `skill_eater_*.py` は上記基底データを一切ロードしていない（grep 結果空）。経済/Husk/輪廻/ROOT は Python ロジックに直接実装され、§2が想定した「基底のオーバーライド」形ではない。

→ 設計を読むと「基底システムが使われている」と誤認しやすく、実装との乖離が見えない。

---

## 2. 目標

各 §2 項目について「設計意図／既存システム／固有データの有無／実装状況」を一覧化し、未実装項目を **TBD** として明確に管理する。設計ドキュメントから該当リストへ辿れるよう紐付ける。

---

## 3. 実装手順

### Step 1 — ギャップリスト作成（`docs/world_a/GAP_03_mapping.md` 新規）
- §2.1〜2.6 各行を表形式で列挙。列: 項目 / 設計マッピング / 既存システム / skill_eater固有データ / 実装状況 / 備考。
- §3.1 の `skills.yaml` は「実装済（正規パス統一済・PLAN-01）」として肯定行に含める。
- 調査で判明した事実（基底は汎用・ローダ未実装）を「調査サマリ」に記載。

### Step 2 — 設計ドキュメントへの紐付け（`DESIGN_A_SKILL_EATER.md`）
- §2 末尾（2.6 の直後、`## 3.` の直前）に `### 2.7 実装実態ギャップリスト（TBD管理）` を追加し、`GAP_03_mapping.md` へリンク＋要約を記載。

### Step 3 — 検証
- §2.1〜2.6 の全項目がギャップリストに含まれていること。
- 各項目に「実装済／TBD」のステータスが付与されていること。

---

## 4. 受け入れ基準

1. `docs/world_a/GAP_03_mapping.md` が存在し、§2の全マッピング項目を網羅している。
2. 各項目に実装状況（実装済 or TBD）が記載されている。
3. `DESIGN_A_SKILL_EATER.md` §2.7 からギャップリストへ辿れる。

---

## 5. 影響範囲・リスク

- **影響**: 設計ドキュメント＋新規ギャップリストのみ。コード・YAMLデータの変更なし。
- **リスク**: 低。既存事実の文書化にとどまる。
- **注意**: 本計画は「可視化」が目的。TBD 項目の実際のクローズ（データ作成・ローダ実装）は別タスク（提案外）。

---

## 6. 関連・フォローアップ

- TBD 項目を順次クローズする場合の作業は、ワールド別データ `data/worlds/skill_eater/<file>.yaml` の作成と `skill_eater_*.py` でのロード実装が必要（別計画）。
- 提案1（PLAN-01）で統一した `data/worlds/skill_eater/` 配下に、これら固有データを置くのが規約上妥当。
