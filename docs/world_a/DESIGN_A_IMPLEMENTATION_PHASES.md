# 🎮 Aの世界（スキル喰い）詳細実装計画書 Part 1

本ドキュメントは、「スキル喰いの異世界倒産」のゲームシステムをフェーズごとに実装していくための詳細な技術・要件設計書です。対象とするアーキテクチャはRPGシステム（UnityまたはReact等の汎用フレームワークを想定した抽象データ・ロジック層）です。

---

## 🟩 Phase 1: 基盤システムと《解析》プロトタイプ

### 1.1 ターゲットとするユーザー体験
**「スキャン＆ハックの全能感」**
プレイヤーが初めてゲーム世界に降り立ち、周囲の人間が「大したことない」あるいは「意外な力を持っている」ことを《解析》によって見透かす優越感を提供します。

### 1.2 実装要件定義

#### 1.2.1 スキルマスターデータ設計 (Data Foundation)
全ての根幹となるスキルの定義。拡張性を確保するため、JSON/YAMLベースでのデータ駆動設計とします。

**データスキーマ (`SkillDef`)**:
- `SkillId` (string): PK
- `Name` (string)
- `Tier` (enum): Common, Rare, Unique, Concept
- `Tags` (List<string>): [Fire], [Combat], [Passive], [Meta] などのタグ。合成や特効判定に使用。
- `MarketValue` (int): 取引時のアルド（通貨）価値。
- `Effects` (List<EffectDef>):
  - `EffectType` (enum): Damage, Heal, Buff, Debuff, Meta
  - `Target` (enum): Self, Enemy, AoE
  - `Formula` (string): 例: `atk * 1.5 + (level * 10)`

#### 1.2.2 解析モードUIの実装 (UI/UX)
フィールド画面や戦闘画面に「解析オーバーレイ」を重ねる機能。

- **フィールド上の解析**:
  - NPCの頭上に `[Tier] Skill Name` をホログラム風UI（緑色のワイヤーフレームなど）で表示。
  - 主人公の解析レベルに応じて情報が解禁。Lv1では「コモン」のみ、Lv5で「レア」、Lv10で「隠しスキル」が赤文字で表示される。
- **戦闘中の解析**:
  - 敵のHPバーの下に「所持スキル一覧」を展開表示。
  - 弱点属性（例：[Fire]弱点）や、敵の行動パターン（次に行うスキル）を事前に可視化する。

#### 1.2.3 状態管理（State Management）
- **PlayerState**: プレイヤーのステータス、現在所持しているスキルのリスト（インベントリ）、各派閥の好感度。
- **EnemyState**: フィールド上のNPCおよび敵の現在状態。所持スキルリスト。

### 1.3 マイルストーン1（成果物）
- [ ] スキルデータ管理クラス `SkillRegistry` がロード・検索可能であること。
- [ ] 敵シンボルをターゲットした際、解析UIが表示され、内部データから対象の所持スキルを正しく抽出・表示できること。

## 🟩 Phase 2: バトルエンジンと《喰らい》の実装

### 2.1 ターゲットとするユーザー体験
**「容赦のない強奪・下剋上カタルシス」**と**「一発逆転の喰らい」**
相手を追い詰め、一番の自慢であるスキルを奪い取ることで、相手を弱体化させ自分を一気に強化する爽快感を提供します。

### 2.2 実装要件定義

#### 2.2.1 資本主義バトルエンジン
ターン制（またはアクティブタイム）のRPG戦闘ロジック。
- 基本コマンド: 攻撃、スキル、アイテム、**喰らい(Devour)**
- 敵AI: 自身の所持スキルリストから最適な行動を選択。特定のスキルを奪われると行動パターンが「恐慌状態」や「物理攻撃のみ」にダウングレードする。

#### 2.2.2 《喰らい (Devour)》システム
本作のコアメカニクス。敵のスキルを強奪する処理。

**強奪成功率の計算式**:
```python
success_rate = BaseChance(20%) + (AnalysisLevel * 5%) + (1.0 - EnemyCurrentHP / EnemyMaxHP) * 50%
if TargetIsUnconscious or TargetHasStatus(Paralyzed):
    success_rate += 20%
```

**強奪成功時のトランザクション（Atomic処理）**:
1. `EnemyState.SkillList.Remove(TargetSkill)`: 敵からスキルを剥奪。
2. `EnemyState.ApplyDebuff(SkillLossShock)`: 敵の全ステータスダウン、および行動キャンセルのショック状態を付与。
3. `PlayerState.SkillTree.Add(TargetSkill)`: プレイヤーのスキルプールに即座に追加。
4. `UI.ShowEffect("Devoured!")`: 強奪成功のド派手な演出。

**強奪失敗時のトランザクション**:
1. `PlayerState.ApplyDamage(Backlash)`: 暴走ダメージを自陣に受ける。
2. `EnemyState.Aggro = Max`: 敵が激怒状態になり、攻撃力がアップする。

### 2.3 マイルストーン2（成果物）
- [ ] 敵と戦闘し、HPを減らした上で《喰らい》コマンドを成功させる一連のループが機能すること。
- [ ] 奪ったスキルがそのターン（または次のターン）からプレイヤーのコマンドとして使用可能になること。

## 🟩 Phase 3: 《合成》システムとダイナミックツリー

### 3.1 ターゲットとするユーザー体験
**「壊れチートを生み出すビルド構築の沼」**
奪った大量のスキルをパズルのように組み合わせ、ゲームバランスを崩壊させるようなシナジーを発見する楽しさを提供します。

### 3.2 実装要件定義

#### 3.2.1 スキル合成アルゴリズム (Synthesis Engine)
2つ（またはそれ以上）のスキルを消費して新しいスキルを生み出す。

- **静的レシピ (Static Recipes)**:
  - 完全に固定の組み合わせ。例: `ID: com_fire_01` + `ID: com_labor_02` = `ID: rar_infrared_vision`。
  - レシピ辞書へのキー照合でO(1)で解決。
- **動的/プロシージャルレシピ (Procedural Synthesis)**:
  - タグを用いた組み合わせ。
  - 例: `[Fire]`タグを持つスキル + `[Heal]`タグを持つスキル = 自動生成スキル「火炎の癒し」。
  - 生成ロジック: `BaseEffect(Heal)` + `Modifier(Add Target Status: Burn)` + `Modifier(Add Self Status: AtkUp)`.
  - 自動生成されたスキルにはランダムな接頭辞・接尾辞を付け、UUIDを割り当てる。

#### 3.2.2 ダイナミックスキルツリー描画 (Dynamic Graph UI)
- プレイヤーの成長軌跡を示す星図UI。
- 根（Root）には《解析》。そこから、喰らったスキルが第一階層のノードとして追加される。
- 喰らったスキル同士を合成すると、二つのノードから線が伸び、新しい合成スキルノードが誕生する。
- グラフ描画ライブラリ（または力学モデルを用いた配置アルゴリズム）を使用し、動的に拡張していくツリーを美しく見せる。

### 3.3 マイルストーン3（成果物）
- [ ] セーフエリア（アジト等）で合成UIを開き、所持スキルを選んで合成できること。
- [ ] 静的・動的の双方のレシピ解決が動作し、新しいスキルがプレイヤーのツリーに登録されること。
