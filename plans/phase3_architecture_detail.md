# フェーズ3：アーキテクチャの洗練 - 詳細実装計画書

## 🎯 目的
複雑に絡み合った状態管理を整理し、論理的な矛盾（バグ）が発生しにくい構造に作り替える。

---

## 🛠 6. 状態遷移（ステートマシン）の厳格化

### 概要
「今、ゲームがどのモードにあるか」を明確に定義し、モード外の操作を完全に遮断する。

### 📝 詳細ステップ (低性能LLM向け小分割)

#### ステップ 6.1: ゲームステートの定義
- [ ] `constants.py` に `GameState` 列挙型 (Enum) を定義する。
    - `EXPLORING`: 通常の探索・移動状態
    - `COMBAT`: 戦闘演出中（ターン処理待ち）
    - `DIALOGUE`: NPCとの会話中
    - `MENU`: インベントリやスキルツリーなどのメニュー展開中
    - `EVENT`: 世界イベントのカットシーン中
    - `PAUSED`: 一時停止状態

#### ステップ 6.2: ステートマネージャーの実装
- [ ] `game.py` の `Engine` クラスに `current_state` フィールドを追加する。
- [ ] `change_state(new_state)` メソッドを実装し、状態遷移時の「開始処理 (on_enter)」と「終了処理 (on_exit)」をフックとして持たせる。
- [ ] 例：`DIALOGUE` 状態に入った時 $\rightarrow$ プレイヤーの移動入力を無効化する。

#### ステップ 6.3: 入力ハンドラのフィルタリング
- [ ] `input_handler.py` の各入力処理の冒頭に、現在のステートを確認するガード節を追加する。
- [ ] `if engine.current_state != GameState.EXPLORING: return` のように、探索状態以外での移動コマンドを無視するようにする。
- [ ] メニュー操作コマンドは `GameState.MENU` の時のみ有効にする。

#### ステップ 6.4: 状態遷移の整合性テスト
- [ ] 「会話中にアイテムを使おうとした場合」に、正しく無視されるか、または「今は使えません」というログが出るかを確認する。
- [ ] 「メニューを開いたまま移動しようとした場合」に、移動せずメニューが優先されることを確認する。
- [ ] 状態遷移のループ（例：メニュー $\rightarrow$ ダイアログ $\rightarrow$ メニュー）でメモリリークや二重表示が起きないか検証する。

#### ステップ 6.5: UIとの連動
- [ ] `render_system.py` で、現在のステートに応じて表示するUIレイヤーを切り替える。
- [ ] `GameState.MENU` の時はマップを暗くし、メニューウィンドウを最前面に描画する。
- [ ] `GameState.DIALOGUE` の時は会話ウィンドウを強調し、他のUI要素を非表示にする。
